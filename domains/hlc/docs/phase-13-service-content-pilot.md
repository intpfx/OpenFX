# Phase 13：社区服务中心内容体验试点

## 目标

Phase 13
把“社区服务中心”的三个既有内容入口从旧式全屏页面改造成同一张手绘地图自然展开的
社区档案。它不是新增一套脱离地图的卡片
UI，而是让场所艺术层成为内容页的主视觉入口：上半部
继续使用服务中心的抽象手绘分区，下半部承接现有 CMS 文字和结构化内容。

## 视觉命题

- 内容页沿用地图的暖纸、墨线、低饱和水彩和朱红强调色，保持“从画中走进场所”的连续感。
- 服务中心分区图以 CSS 背景承担主视觉，不把现实照片、写实视频或 CMS
  图片直接展示在前台。
- 页面以地点名称、栏目序号、内容标题和文字记录建立层级，不使用通用仪表盘卡片或编号圆点。
- 桌面端采用左侧场所画面、右侧纸页内容；竖屏端改为上下连续阅读，不产生横向溢出。

## 三项服务

| 服务     | 内容语义             | 既有数据入口   | 前台呈现                         |
| -------- | -------------------- | -------------- | -------------------------------- |
| 走进社区 | 组织、团队与社区介绍 | `intro-page`   | 文字档案；人物照片不直接展示     |
| 社区动态 | 通知、活动与社区故事 | `list-page`    | CMS 动态列表；图片不进入试点样板 |
| 社区示范 | 治理实践与可复用经验 | `example-page` | 文字案例；不展示现场照片或视频   |

三个入口共用
`createSceneContentViewModel()`。模型统一提供场所、服务、栏目序号、引导文字、
强调色、服务切换导航和 `abstract-only`
媒体策略；今后扩展其他场所时不需要复制页面结构。

## 交互闭环

- 地图、场所详情或深链接都可以直接打开对应内容。
- 三项服务在同一内容页内切换，并替换当前服务历史记录，避免连续切换制造多层返回栈。
- “返回地图”始终回到社区服务中心，地址退回
  `#place=service-center`，不会残留服务参数。
- 旧内容脚本完成事件绑定后才恢复深链接，避免首次刷新时只出现装饰层而正文仍隐藏。
- 页面继续复用现有 CMS DOM 和接口；本阶段没有改写存储、编辑或发布流程。

## 验收基线

- 桌面和 390 × 844 竖屏均可打开、切换和退出三项服务。
- 竖屏页面宽度等于视口宽度，不出现横向滚动。
- `abstract-only` 内容中可见的 `img`、`picture` 和 `video` 数量为 0。
- 直接刷新任一 `#place=service-center&service=...` 深链接仍能显示完整内容页。
- CMS 尚无正文时显示有意设计的整理中状态，而不是空白或旧版编辑器骨架。
