# OpenFX 首页定位海报背景设计

## 目标

在不改变“首页首先是项目浏览器”的前提下，把 Map Poster
的城市海报能力融入首页背景。首页使用
浏览器的真实设备定位获得用户当前坐标，以该坐标生成城市级地图海报，并将海报作为低对比度背景。
Map Poster 项目卡片继续保留，仍然是一键进入完整生成器的独立入口。

首次访问且浏览器需要询问定位权限时，页面进入一次短暂、明确的授权焦点状态：底部出现最高层级的
紧凑胶囊控制条，胶囊以外的首页内容统一模糊、降透明并暂时退出交互。授权结束后，焦点状态解除，
胶囊收束为低干扰的城市背景状态条。

## 已确认的产品决策

- 使用 `navigator.geolocation` 获取真实设备位置，不使用 IP
  推断、语言、时区或其他近似定位。
- 精度目标是可靠区分用户所在城市，不追求街道或建筑级定位，也不在界面展示原始经纬度。
- 首页首屏结构、OpenFX 标识、三列项目浏览器、搜索、项目计数、MESSAGE、版本信息和 13
  张卡片保持不变。
- Map Poster 卡片继续打开现有详情面板；首页背景不是卡片入口的替代品。
- 不新增 Hero、口号、筛选器、持续背景动画、WebGL、视频或客户端运行时依赖。
- 不增加新的 HTTP 路由。首页复用现有
  `POST /api/map-poster/render`，通过其直接坐标输入生成背景。
- 未授权、拒绝、超时、精度不足或地图服务失败时，首页恢复现有中性背景，不展示猜测城市或错误
  海报。

## 视觉结构

### 背景层

新增一个仅负责展示的 `HomepagePosterBackground` 层，位于首页内容之下，并标记
`aria-hidden="true"`。背景层使用现有 Map Poster SVG 输出，采用 `cover`
裁切，以一层浅色遮罩和
现有网格控制对比度。项目卡片、文字和交互控件必须持续满足可读性要求；海报是环境质感，不成为
新的视觉主角。

等待定位前不使用东京或其他预设城市冒充当前位置。页面沿用当前中性背景，只有真实坐标成功渲染
后才交叉淡入城市海报。

### 首次授权胶囊

授权胶囊固定在首页底部居中，层级高于品牌、项目浏览器和原有底部控件：

- 桌面端高度为 `58px`，最大宽度为 `760px`，宽度不超过视口减 `68px`。
- 胶囊使用完全圆角、轻量蓝色描边、半透明浅色表面和克制阴影。
- 左侧保留两行信息：主文案“用你所在的城市生成首页背景”，次文案“设备定位仅用于生成城市
  海报，不保存原始位置”。
- 右侧主按钮文案为“允许定位并生成”，点击区域高度不小于 `44px`，按钮同样使用完全圆角。
- 胶囊内提供低强调的“暂不使用”操作。它不能放在模糊层中，也不能依赖点击胶囊外部关闭。

授权胶囊激活时，胶囊以外的首页使用约 `6px` 模糊、轻微降透明和浅色遮罩。背景内容暂时设置
`inert`，胶囊使用 `role="dialog"`、`aria-modal="true"` 和可访问标题。焦点进入主按钮；按
Escape 或选择“暂不使用”会恢复首页，并在当前页面实例内不再重复打扰。

### 请求中与完成态

点击主按钮后，胶囊保持尺寸和位置不变，只把文案切换为“在浏览器提示中允许位置访问”，操作区
切换为“等待授权”。网页不绘制伪造的权限弹窗；浏览器或操作系统的原生授权界面是唯一权限决策
入口。

生成成功后，模糊与遮罩退场，海报以约 `480ms` 交叉淡入。授权胶囊收束为高度 `42px` 的状态
胶囊，只显示“背景 · {城市}”、`Map Poster` 来源和“重新定位”。完成态不抢占搜索、MESSAGE 或
项目计数的点击区域；桌面端位于底部状态区，窄屏时排列在现有项目命令条上方。

移动端授权胶囊宽度为视口减
`28px`。为保持紧凑，隐藏英文标签和次级隐私说明，但保留主文案、“暂不使用”和不小于 `44px`
的主按钮。胶囊不得产生横向滚动或遮挡系统安全区。

## 组件与状态边界

首页新增以下独立单元，避免继续扩大 `App.tsx` 的职责：

1. `HomepageLocationPoster.tsx`
   - 组合背景、授权胶囊和完成态胶囊。
   - 管理权限检查、焦点进入与恢复、对象 URL 生命周期及用户动作。
   - 通过回调或显式状态与首页壳协作，不读取项目卡片内部状态。
2. `homepage/location-poster.ts`
   - 保存纯函数和类型：状态归一化、Geolocation
     错误映射、精度判定、渲染请求构造和地点标签选择。
   - 不直接访问 DOM、`navigator`、`fetch` 或存储。
3. `entry/web/server/map-poster.ts`
   - 继续作为唯一海报渲染服务边界。
   - 对“提供直接坐标但未提供展示地点”的请求增加反向地点解析，并把解析后的城市/国家作为
     附加响应字段返回。

状态机固定为：

```text
checking → needs-permission → requesting → rendering → ready
    ├──────────────→ dismissed
    ├──────────────→ denied
    ├──────────────→ unavailable
    └──────────────→ error
```

只有 `needs-permission` 和 `requesting` 使用模糊焦点状态。已经授权的回访直接进入
`rendering`，使用非模态小胶囊提示生成进度，不重新模糊首页。`dismissed`、`denied`、
`unavailable` 和 `error` 均立即恢复完整项目浏览器。

## 定位与渲染数据流

1. 首页挂载后，若 Permissions API 可用，查询 `geolocation` 权限状态。
2. `prompt` 或无法查询时显示授权胶囊；`granted` 时直接获取设备位置；`denied`
   时不触发浏览器提示，并显示低干扰的权限不可用状态。
3. 用户点击“允许定位并生成”后调用 `navigator.geolocation.getCurrentPosition`：
   - `enableHighAccuracy: true`
   - `timeout: 12_000`
   - `maximumAge: 300_000`
4. 只有精度不超过 25 公里的结果进入城市背景渲染。更低精度不能可靠满足城市级要求，胶囊
   显示“定位精度不足”，提供重试和暂不使用。
5. 客户端向现有 `/api/map-poster/render` 发送一次 POST，请求包含
   `latitude`、`longitude`、
   `theme: "japanese_ink"`、`distanceMeters: 6_000`、`width: 1_600` 和
   `height: 1_000`。首页不传伪造城市名。
6. 服务端使用精确坐标获取 OSM 数据，同时通过 Nominatim reverse endpoint 解析城市级标签。
   地点字段优先级为 `city → town → municipality → village → county`；国家使用返回的
   `country`。反向解析失败不改变地图中心，海报使用中性 `LOCAL AREA / OPENSTREETMAP`
   标题，状态胶囊不显示未经确认的城市名。
7. 服务端返回 SVG、中心点、统计信息和可选的解析地点。客户端把 SVG 建为 `image/svg+xml`
   Blob 与对象 URL，替换背景时或组件卸载时调用 `URL.revokeObjectURL`。

坐标只存在于当前页面内存、单次 HTTPS
请求体和服务端请求生命周期中。客户端不把经纬度、城市或 SVG 写入
localStorage、sessionStorage、IndexedDB、cookie、URL、日志或分析事件；服务端不新增
位置缓存、数据库记录或审计字段。“暂不使用”只影响当前页面实例，不创建新的客户端持久化格式。

## 权限、失败与恢复

- 用户拒绝或关闭原生权限提示：解除模糊与 `inert`，显示“未启用城市背景”，提供“重新定位”。
- 浏览器已永久拒绝：不重复调用 Geolocation；提示用户需要在浏览器站点设置中重新开放权限。
- Geolocation 不可用或页面不是安全上下文：不显示授权焦点，沿用中性背景。
- 获取位置超时：恢复首页并提供一次显式重试，不自动循环。
- 精度超过 25 公里：不发送坐标，不生成可能属于相邻城市的海报。
- Overpass 或 SVG 渲染失败：撤销临时对象 URL，沿用中性背景；错误只由状态胶囊简短播报，
  不阻断搜索、卡片或 MESSAGE。
- Nominatim 反向地点解析失败：继续使用真实坐标生成海报，但使用中性标题且不在状态胶囊显示
  未经确认的城市名。
- 用户点击“重新定位”：重新进入显式请求流程；若权限仍为 `granted`，不显示模态模糊，只展示
  生成进度。

## 动效与可访问性

- 模糊只应用在胶囊之外的内容容器，胶囊本身不能是该容器的后代，避免 `filter`
  创建的层叠上下文降低胶囊层级。
- 首次焦点状态记录进入前的焦点，关闭后恢复原元素；原元素不存在时回退到 OpenFX 标识按钮。
- 状态变化使用一个 `aria-live="polite"` 文本节点播报，不让整个首页或项目列表成为 live
  region。
- 原生权限请求必须由用户点击触发；Enter 和 Space 只触发胶囊中已聚焦的对应按钮。
- `prefers-reduced-motion: reduce`
  下关闭背景交叉淡入、胶囊位移动效和等待脉冲，状态直接切换。
- 模糊焦点仍然保留，因为它是用户明确选择的视觉层级而非运动效果；所有文本和按钮继续满足对比度
  与可见焦点要求。

## 测试设计

### 纯函数与组件测试

- 权限状态到首页状态机的映射。
- Geolocation 的 denied、timeout、unavailable 错误文案。
- `accuracy` 在 25 公里边界内外的判定。
- Map Poster 请求只包含允许字段，并使用确认的主题、尺寸和范围。
- 地点标签优先级和反向解析失败回退。
- 成功、重试、暂不使用和组件卸载时对象 URL 的撤销。
- 焦点进入胶囊、背景 `inert`、Escape 退出和焦点恢复。

### 服务端测试

- 直接坐标请求不会执行正向 geocoding。
- 缺少展示地点时执行反向地点解析，并把解析标签传给 SVG renderer。
- 反向解析失败仍以原坐标生成地图，不伪造城市名。
- 反向地点请求继续使用超时、固定 User-Agent 和输入边界，不接受客户端提供任意上游 URL。

### 浏览器验收

使用内置浏览器验证 1440×900、1024×768 和 390×844：

- 权限为 `prompt` 时，只有 `58px` 胶囊清晰可交互，胶囊之外内容模糊且可聚焦元素为 0。
- 授权胶囊、原生权限等待和错误状态之间不改变胶囊边界或页面滚动位置。
- 允许定位后背景来自设备实际城市，状态胶囊显示同一城市，不暴露坐标。
- 成功后 Map Poster 卡片、搜索、13 / 13、MESSAGE 和版本信息位置与行为不变。
- “暂不使用”、拒绝、超时、精度不足和服务失败均恢复完整首页。
- 移动端胶囊无横向滚动、不遮挡底部命令条，所有主控件点击高度不小于 44px。
- 减弱动效模式没有背景交叉淡入、胶囊位移或等待脉冲。

## 非目标

- 不把定位能力放入 Map Poster 项目卡片内部，也不自动打开 Map Poster 面板。
- 不保存用户位置、城市海报或授权选择到任何客户端持久化存储。
- 不根据访问者位置改变项目排序、搜索结果、内容语言或任何服务端业务行为。
- 不请求后台定位、持续定位或 `watchPosition`。
- 不新增地图供应商、分析 SDK、第三方定位 SDK、客户端地图运行时或部署配置。
- 不在本设计阶段推送、发布或部署。
