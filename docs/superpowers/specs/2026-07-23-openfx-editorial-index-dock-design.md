# OpenFX Editorial Index Dock 设计

## 背景

OpenFX 首页底部已经把构建信息、Map Poster 城市背景状态和项目命令区合并为一个语义化
Dock，但当前视觉仍像传统工具栏：完整外框、毛玻璃、阴影、三栏等权分割和密集的同级文字削弱了
首页的网格、留白与编辑式气质。

本次重设计采用用户确认的 C 方案「Editorial Index」。目标不是再次拆分功能，而是在保留统一
组件和现有交互的前提下，以两条文字基线重新组织信息层级。

## 目标

- 与 OpenFX 的白色网格、黑色正文和蓝色点睛保持一致。
- 让项目计数与搜索成为视觉中心，构建与背景信息退居元数据层。
- 通过字号、字距、基线和留白建立层级，减少容器与分割线。
- 保留当前搜索、留言、详情返回、Proxy、定位和可访问性行为。
- 桌面和移动端都保持稳定高度，不因状态切换产生重排或横向滚动。

## 非目标

- 不改变首页三列项目浏览器、卡片、背景海报或详情面板设计。
- 不修改定位授权流程、Map Poster API、服务端逻辑或隐私约定。
- 不新增筛选器、图标库、动画依赖、路由或持久化格式。
- 不把独立的首次定位授权胶囊合并进 Editorial Dock。

## 视觉结构

### 外层

`HomepageFooterDock` 继续作为唯一的语义化 `<footer aria-label="首页控制栏">`。桌面端取消
完整外框、圆角、毛玻璃和阴影，使用透明背景与一条底部细线形成编辑式索引带。

Dock 不再呈现三个等权方框。内部改为两列：

1. 左侧索引区占据剩余宽度，包含上下两条文字基线。
2. 右侧主操作跨越两行，以一条短竖线和索引区分隔。

现有 `left`、`middle`、`right` 数据所有权可以保留，但呈现层需要把左、中内容组合到元信息
基线，把右侧的计数与搜索组合到主索引基线。组件接口可以调整为更能表达 `meta`、`index` 和
`action` 的命名；不得让 `App.tsx` 重新承担布局细节。

### 第一条基线：元信息

从左到右显示：

- `BUILD`：弱化的全大写标签。
- `local00`：短构建哈希；完整日期和时间保留为可访问文本或 `title`，不占据主视觉。
- 蓝色状态点。
- `BACKGROUND`：弱化的全大写标签。
- `绵阳市`：当前城市名，权重高于标签但低于项目索引。
- `© OSM`：指向 OpenStreetMap copyright 页的归属链接。
- 重新定位控件：视觉上使用简洁的 `↻`，提供完整中文 `aria-label`。

不再显示冗余的 `Map Poster` 文字。城市背景、OSM 归属和重新定位已经足以表达功能。

### 第二条基线：项目索引

从左到右显示：

- 蓝色、稍大的当前结果数，例如 `13`。
- 更小、更弱的总数，例如 `/ 13`。
- 搜索输入。占据索引区剩余宽度，默认文案为 `Search the OpenFX index…`。

搜索框不绘制完整边框。默认态依靠文字与基线存在，聚焦时只出现一条蓝色底线。

### 右侧主操作

`MESSAGE` 位于独立的右侧区域，跨越两条基线。它使用蓝色状态点、全大写文字和较大字距，不使用
实心按钮或胶囊。右侧区域与索引区之间只保留一条短竖线。

详情态下主操作改为 `← 返回项目卡片`；留言态改为 `SEND`；Proxy 态改为 `OPEN`。主操作宽度
需要预留最长常用文本，避免切换时 Dock 横向跳动。

## 字体层级

沿用项目现有字体，不新增 Web Font。

- 元信息标签：约 `0.48–0.52rem`，字重 650，字距约 `0.12em`，全大写。
- 元信息值：约 `0.56–0.62rem`，常规字距，次级文字色。
- 城市名：约 `0.62–0.68rem`，字重 650，正文色。
- 当前项目数：约 `0.78–0.86rem`，字重 700，OpenFX 蓝。
- 总项目数：约 `0.55–0.6rem`，次级文字色。
- 搜索文字：约 `0.68–0.74rem`，自然字距，正文色。
- 主操作：约 `0.58–0.64rem`，字重 700，字距约 `0.1em`，OpenFX 蓝。

最终数值可以在浏览器验收中小幅调整，但层级顺序不得改变。

## 状态行为

### 默认与搜索

上行显示构建和城市背景信息，下行显示项目计数与搜索，右侧显示 `MESSAGE`。搜索只更新计数与
卡片结果，不改变 Dock 高度或结构。

### 留言

第二条基线原位切换为返回、`MSG` 和留言输入；右侧主操作切换为 `SEND`。不得新增外层容器，
不得改变 Dock 高度。Escape 和返回按钮继续恢复搜索态及焦点。

### 项目详情

Map Poster 在内的详情面板打开后，定位控制继续由 `HomepageLocationPoster` 暂停。元信息行只
保留可用的构建信息，不渲染空背景占位。项目索引行隐藏，右侧显示 `← 返回项目卡片`。关闭后仍
恢复到原卡片按钮。

### Proxy

第二条基线原位切换为返回按钮和 URL 输入；右侧显示 `OPEN`。现有提交、Escape 和 iframe
行为保持不变。

### 定位生成、错误和授权

- 正常生成、失败、拒绝和不可用状态占据元信息行的背景位置，使用短状态文字。
- 长状态单行省略，不得挤压项目索引或右侧主操作。
- 首次定位授权仍使用独立的最高层胶囊。
- 授权期间首页和 Editorial Dock 继续模糊，并设置 `inert` 与 `aria-hidden`。
- 独立实时播报区域保持在 inert Dock 之外。
- 海报背景与 OSM 归属所有权不变，每个状态仍只出现一个可访问的归属链接。

## 响应式

### 宽屏与桌面：`>900px`

- Dock 参与首页第三行网格，不使用 fixed 定位。
- 视觉高度约 52–58px。
- 元信息和项目索引各占一条紧凑基线；右侧主操作跨两行。
- 1024px 左右优先缩短或隐藏完整构建时间，其次压缩搜索宽度；城市名、计数和主操作保持可见。

### 移动端：`<=900px`

- Dock 固定在安全区上方，使用轻薄的半透明白色底色保证地图背景上的可读性。
- 不使用大胶囊、强阴影或三等分外框；允许使用小圆角与上下细线。
- 上行承载构建和背景元信息，下行承载计数、搜索和主操作。
- 两行交互区域都保证至少 44px 触控高度。
- 在 390px 下优先保留城市名、当前计数、搜索和主操作；隐藏完整构建时间和非必要英文标签。

断点两侧都必须满足：

- 无横向滚动。
- 无文字重叠。
- 无状态切换导致的高度跳动。
- 交互元素保持明确的可见焦点。

## 动效

普通模式只允许搜索底线、文字颜色和状态点做不超过 180ms 的短过渡。Dock 本身不位移、不缩放，
状态切换不使用扫描线或持续动画。

`prefers-reduced-motion: reduce` 下移除上述过渡。

## 组件与测试

- `HomepageFooterDock.tsx` 继续负责语义外壳与 Editorial Index 布局。
- `HomepageLocationPoster.tsx` 继续负责定位、海报、归属、授权焦点和状态生命周期。
- `App.tsx` 只提供构建、状态和命令内容，不直接声明 Dock 的网格或装饰。
- 更新 `entry/web/README.md`，记录 Editorial Index 的层级和响应式规则。

测试至少覆盖：

- 单一语义化 footer 和稳定的元信息、索引、主操作顺序。
- 默认、留言、详情和 Proxy 状态不产生第二个外层 Dock。
- 桌面无完整外框、胶囊、毛玻璃或阴影。
- 桌面两条基线和跨行主操作。
- 移动端两行结构、44px 触控目标和 390px 无溢出约束。
- 定位授权仍独立于 Dock，并保持 inert、实时播报和唯一 OSM 归属。
- 搜索、计数、焦点恢复、Escape 和主操作行为不回归。

## 浏览器验收

使用内置浏览器优先，无法使用时回退 Safari。验证 1440×900、1024×768、901×844、
900×844 和 390×844：

- 文字层级与设计稿一致，搜索是视觉中心。
- 构建和背景信息明显弱于项目索引。
- `MESSAGE` / `SEND` / `OPEN` / 返回切换不引发宽度或高度跳动。
- 所有状态无横向滚动、重叠或小于 44px 的移动端交互目标。
- 定位授权胶囊仍处于最高视觉层，Dock 正确模糊且不可交互。
